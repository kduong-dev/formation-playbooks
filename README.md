# formation-playbooks

Orchestrates the frontend and backend service for reMarkableShelf, for both
local development and server deployment. The service `.env` file and
docker-compose.yml are generated by Ansible from declarative YAML files.
Docker Compose runs the stack behind Traefik.

Modeled on [trading-formation](https://github.com/trading-core/trading-formation),
scaled down for a single backend service.

## Layout

```
formation-playbooks/
  playbook.yml              entry point — loads vars, renders the server's formation.yml
  secrets.yml                ansible-vault encrypted (Google Books API key, reMarkable SSH password) — gitignored, local only
  services.yml               domains, the server's host/port, the frontend's container port
  resources.yml               the sqlite db path (container vs local) and named volumes
  library.yml                secrets, config — kinds referenced by cmd/server/formation.yml
  tasks/
    render-service.yml       merges the resource kinds a service declares into its .env
  templates/
    service.env.j2           KEY=VALUE per line
    docker-compose.yml.j2    compose definition derived from services.yml + resources.yml
    traefik-static.yml.j2    Traefik routing for both server and local domains
  backend/
    Dockerfile                Go build for the server binary
  frontend/
    Dockerfile                Vite build served via nginx
    nginx.conf
  run-services.sh            render / start / up / kill / delete
```

The backend declares what it consumes in its own repo:

```yaml
# reMarkableShelf/backend/cmd/server/formation.yml
resources:
  secrets: [google_books, remarkable_ssh]
  config:  [server]
  stores:  [sqlite]
```

The kinds (`secrets`, `config`, `stores`) are top-level vars in `library.yml` /
`resources.yml`. Each named resource maps to a dict of env-var key/value pairs.

## Prerequisites

- **Docker** with WSL2 integration enabled (if on Windows)
- **Ansible** — for rendering the env file, compose file, and Traefik routes
- **Go 1.27+**, **Node.js LTS** (only needed for building outside Docker)

## Secrets

`secrets.yml` is encrypted with ansible-vault and is **not committed to git** —
it stays local, same as `trading-formation`. The vault password lives in
`.vault_pass` (also gitignored).

```bash
# generate a vault password (one time, per machine)
openssl rand -base64 32 > .vault_pass
chmod 600 .vault_pass

# view/edit secrets
ansible-vault edit secrets.yml --vault-password-file .vault_pass

# encrypt a new plaintext file
ansible-vault encrypt secrets.yml --vault-password-file .vault_pass
```

Share `.vault_pass` and `secrets.yml` with anyone who needs them out-of-band
(password manager), never via git.

## Domains

| | Frontend | API |
|---|---|---|
| **Server** | `remarkable-shelf.local` | `api.remarkable-shelf.local` |
| **Local dev** | `remarkable-shelf.localhost` | `api.remarkable-shelf.localhost` |

`.localhost` resolves to `127.0.0.1` natively in all modern browsers — no
hosts file or DNS setup needed locally. Server domains require `/etc/hosts`
(or DNS) pointed at the server once one exists.

## Usage

```bash
# render .env / docker-compose.yml / Traefik routes from secrets.yml + services.yml + resources.yml + library.yml
./run-services.sh render

# render, build, and bring the stack up
./run-services.sh start

# bring it up without rebuilding
./run-services.sh up

# tear down
./run-services.sh kill
```

Access locally at `http://remarkable-shelf.localhost` (frontend) and
`http://api.remarkable-shelf.localhost/api` (backend), both through Traefik
on `:80`.
